# YENI engineering status | 15 November 2026

The Windows workspace runs an integrated ETABS capture, calculation and reporting pipeline. The live column axial branch uses the assigned design combinations, reads native forces, evaluates the numerical axial limit and preserves the result under one RunID. The current release states are `NOT_PROVEN` for formal compliance and `NOT_READY` for engineering release.

This report is based on the local integration workspace at committed baseline `9f87630`. The measurements below describe the working version of the engine and workspace. This branch publishes the status report. Integration of the local implementation into a code branch is a separate open item.

## Architecture and execution

```text
English workspace and project combination assignments
  -> existing combined live endpoint
  -> single locked ETABS model session
  -> R03 source catalog and exact combination binding
  -> native source rows and calculation owners
  -> immutable RunID input and stage receipts
  -> workspace results, JSON export and printable HTML
```

The gateway attaches to the selected ETABS process and verifies the model and API units. The axial branch uses the same attached model for geometry, material and selected `FrameForce` rows. It preserves the ETABS object `UniqueName`, analysis element, station, combination and output step. Temporary result selections are verified and restored. Static forces remain signed rows. Spectrum results retain their component envelope semantics.

Settings resolve project defaults from one engine-owned design group profile against the verified ETABS catalog. The live axial check receives the exact selected names and records the group assignment alongside the source and result. Browser overrides apply to the selected model. The workspace separates the assignment for a future run from the combinations recorded in a saved result.
